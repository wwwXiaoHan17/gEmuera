# gEmuera 日志系统大白话教程（从零学会）

> 这份教程写给**非程序员**的玩家/测试者。技术速查看另一份
> [`日志与调试使用说明.md`](日志与调试使用说明.md)。

---

## 一、日志是什么？（先打个比方）

日志 = 游戏的**行车记录仪**。

- 平时它不录（或只记"出大事"），因为一直录会耗电、占内存、写满磁盘。
- 出问题时，你把记录仪打开，**复现一遍问题**，它就录下了刚才发生了什么。
- 开发者靠这份记录，不用现场也能猜到"哪里坏了"。

所以记住一句话：**平时别开，出问题时开、复现、抓日志、发人。**

---

## 二、你只需要会 3 件事（其他都别碰）

打开启动器「**设置 → 调试 / 日志**」页，只用这 3 个：

| 第几步 | 做什么 | 在哪 | 人话 |
|---|---|---|---|
| 1 | 调**日志等级** | 「日志等级」下拉框 | 告诉它"记多细"（`info`/`debug` 记得多） |
| 2 | 开**持续文件日志** | 「持续文件日志」开关 | 让记录存成硬盘文件，才能发人 |
| 3 | **看 / 导出** | 「导出日志 / 导出诊断包」按钮 | 现场回放 or 打包发人 |

> **最安全的默认**：日志默认已开启、等级 `warn`，什么都不动。它只是"开得最少"，不会弄坏游戏。
> （游戏内悬浮球诊断面板已于 2026-09-19 移除，配置都改在启动器设置页。）

## 三、几个词，一句话解释（看设置页不再懵）

| 你看到的词 | 大白话 | 什么时候用 |
|---|---|---|
| **等级 level** | 日志的"详细程度"：`error`=只记大错，`warn`=加警告，`info`=加普通信息，`debug/trace`=记到每一个动作 | 默认 `warn`。查具体问题时才升到 `debug` |
| **类别 category** | "哪些模块"的记录，如图片、触摸、输入、存档 | 配合 preset 自动开，一般不用手点 |
| **ring buffer** | 内存里保留的**最近 N 条**日志，导出时一起打包 | 不用管，只是"看最近发生的事" |
| **限流 rate limit** | 防止某条日志**刷屏**把手机搞卡 | 开着就好，默认安全 |
| **脱敏 redaction** | 把路径/长文本**截断或打码**，保护隐私、控制体积 | 开着就好 |
| **调试档 debug_model** | 一套"语言 + 等级 + 开关"的**预设组合** | 一般由 preset 自动选，不用手点 |
| **镜像到 Godot** | 把日志也**打印到桌面调试控制台** | 只在你连电脑看时才用，手机别开 |
| **诊断包** | 把日志 + 配置 + 机型信息**打包成一个文件** | 发给开发者时用，最省事 |

## 四、遇到问题，查什么、怎么开

进阶玩法：在 `config.toml` 里写 `[quick_debug] preset = "..."`（面板移除后预设只能这样配）。

| 我遇到... | 配哪个 preset | 还要开 file_sink | 看哪里 |
|---|---|---|---|
| 点按钮没反应 / 触摸错位 / 划不动 | `touch_input` | ✅ | 导出 |
| 图片不显示 / 闪白 / 立绘卡 | `image_ui` | ✅ | 导出 |
| 游戏卡顿 / 掉帧 | `performance` | ✅ | 导出（里面有性能采样）|
| 存档读不了 / 存不上 | 额外模块 `load_save` | ✅ | 导出 |
| 装了 APK 打不开 / 找不到游戏 | `apk_issue` | ✅ | 导出 |
| 声音 / 资源加载异常 | 额外模块 `resource` | ✅ | 导出 |
| 全都不对 / 说不清 | `apk_issue`（最全） | ✅ | 导出 |

## 五、完整排查流程（照着做）

1. 打开启动器「**设置 → 调试 / 日志**」页。
2. 打开**持续文件日志**（`file_sink`）；想记更细就把**日志等级**调到 `info`/`debug`。
3. 点「**立即应用**」，然后进游戏。
4. **复现问题**（重做一遍刚才卡住/报错的操作）。
5. 日志持续写在 `user://gemuera_runtime_*.log`；退出游戏回启动器点「**导出诊断包**」也可以。
6. 把文件发给开发者，**附上机型 + Godot 版本**。

---

## 六、为什么"平时只记警告以上"？（一句原理）

日志默认开启、等级 `warn`（警告以上）+ 限流 + 脱敏，是**有意设计的**：记录要花 CPU 和内存，一直全开会让低端机更卡。所以"调高等级去复现问题 → 拿到就调回"，才是正确用法。

## 七、术语对照（技术名 → 人话）

| 技术名 | 人话 |
|---|---|
| `LoggingEnabled` / `[logging] enabled` | 记录仪总开关 |
| `level` / `log_level` | 记录多细 |
| `file_sink` | 存成文件 |
| `rate_limit` | 防刷屏 |
| `redaction` | 打码/截断 |
| `ring buffer` | 最近 N 条 |
| `preset` | 一键场景预设 |
| `diagnostic_package` | 诊断包 |
| `event_id` | 每条日志的"身份证"（哪个动作发的）|
| `session_id` | 本次启动的编号（日志文件名里的时间）|
