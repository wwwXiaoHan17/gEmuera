## 关键决策与 Why

1. **修 legacy-runner 的**机械部分**，但拒绝为真漂移发明断言。**
   盘点把 105 个断言符号分成两类：**可机械映射的纯改名**（`M0Runner`→`LegacyRunner` 等）与**接口真实演进**（队列排空职责从 `EmueraMain`/`GenericUtils` 迁进 `EmueraGpuRenderComponent`/`EmueraTextRenderComponent`，`uiQueue` 改成环形缓冲）。
   前者照改；后者**只列不改**——"现在应该断言什么"是契约决策，需要了解该模块的人定，猜一个等于把守卫改松。
   验收标准因此定成"**让失败变得可读**"而不是"让测试变绿"：before 是 6/6 停在文件缺失、**断言执行数 0**；after 是 5 个全绿、第 6 个执行 **221 次断言求值**、4 条失败各指名契约与符号。
2. **校验器的"保序"检查按子序列定义，而不是逐行相等。**
   纯移动允许区间交错（`GenericUtils.cs` 的 13 个区间就高度交错），所以不能要求分片正文与原文逐行连续；但**成员重排**必须能被发现。定义成"分片正文是基线主文件正文的**子序列**"同时满足两点。
   这条缺口是真问题：C# 里 `static readonly` 字段初始化器**按文本顺序执行**，字段换序是真实行为风险，而行多重集比对**对顺序完全不敏感**。本次就有一位执行 agent 上报"疑似成员换序"，主会话手工复核判定是误报——但**当时的工具确实看不见这类问题**。
3. **拒绝把"顺手把空行折叠掉"当改进。** 三批拆分都产生了若干连续空行（纯删除的必然产物）。折叠它们会把 `insertions=0` 的纯删除 diff 变成非纯删除，收益是纯美观、代价是破坏最强的举证形式。统一保持原样。
4. **csproj 排除 `Build\**` / `reports\**` 而不是靠纪律。** 这两个目录都是 gitignore 的产物/临时区，默认 glob 却会收录它们。本次真实踩过：把过期的 `obj/AssemblyInfo.cs` 挪进 `Build/` 后产生 35 个 CS0579，且**报错指向的文件看起来毫不相干**。用 csproj 排除把这类事故变成不可能。

## AI 表现复盘

- **有效**：
  - **把"守卫修复"的验收标准定为"失败可读"而非"变绿"**，从根本上避免了"为了让测试过而放宽断言"这条滑坡。执行 agent 也据此刻意没有动那 4 条真漂移，并明确写"不能说守卫已恢复"。
  - **子代理主动纠正了主会话的盘点错误**，而且三处都是对的：① 陈旧路径是 **15 处**不是 14；② 我把 4 个**存在于 `.ps1` 里**的符号误判为"已消失"——因为**我只搜了 `.cs`**；③ 我给的 `CaptureM0SettlementFingerprint → CaptureSettlementFingerprint` 映射**是错的**，正确是 `→ CaptureLegacySettlementFingerprint`（前者是另一个已存在符号，按我的映射改会让断言必红）。
  - **对保序检查做了人为构造验证**：把分片副本按成员边界对调两段后，工具输出 `MULTISET: PURE MOVE`（多重集完全看不见重排）但 `ORDER: VIOLATION`，exit 3 —— 用输出本身证明了这条新检查不是摆设。
- **低效**：
  - **我的符号存在性搜索范围不足**（只搜 `.cs`）直接产出了一份错误的"9 个真漂移"清单，并把它写进了 `FILE_STANDARD`。这是典型的"**结论来自不完整搜索却当成事实**"。已在 §6.4 修正并把这个陷阱写成明文。
  - 派发时给的符号映射表**未经逐条 grep 验证**就下发了（`CaptureSettlementFingerprint` 那条）。虽然执行 agent 挡住了，但正确做法是我下发前就验证——**映射表也是断言，也要验证**。

## 教训 → 具体优化动作

1. **"某符号不存在"这种结论，搜索范围必须显式写出来并覆盖 `.cs` + `.ps1` + `.psm1` + `.json`。**
   只在 `.cs` 里搜不到 ≠ 符号不存在。本轮 4 个假阳性全部来自范围不足。
2. **给子代理的任何符号映射表，下发前逐条 grep 验证**；并明确要求子代理"用之前自己再验一遍，错了要报回来"（本轮正是这条救了场）。
3. **修坏掉的守卫时，先把验收标准定成"失败信息变可读"，再谈变绿**；真漂移一律清单化、不猜。
4. **纯移动校验器的口径已固化**（`tools/pure-move/README.md` 写明它证明什么、**不**证明什么）：
   证明"行内容无增删 + 正文保序"；**不**证明编译通过、不证明运行期行为、不覆盖 §6 六类钉扎与引用路径。
5. **本轮顺手修了校验器自身的一个盲区**：原归一化把所有 `^using\s` 开头的行都丢掉，导致 `using (var x = ...) { }` 这类**方法体内的真实语句**被静默忽略（实测全仓 79 行、18 个文件）。
   已改为只丢 using **指令**、保留 using **语句**，并直接验证谓词（`using System;`→丢、`using (var s = Open())`→留），且重跑三个家族无回归。
