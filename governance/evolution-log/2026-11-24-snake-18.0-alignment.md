## 2. 关键决策与 Why

1. **审计起点取 17.2 而不是照搬 AGENTS.md 的「Skiav12.1」**：`governance/evolution-log/2026-11-14-snake-17.2-alignment.md` 记录 11-14 已对齐 17.2、11-15 加了 div-align。上游没有 tag，用 CHANGELOG 版本提交定位（`git show <提交>:CHANGELOG.md | grep -m1 "^## "`）：12.1.0=`4849416`、13.0.0=`5717045`、17.2.0=`8005f9f`、17.4.0=`2537080`、18.0.0=`7154549`。
2. **不用旧的差异比对工具**：`tools/dialect-inventory/Invoke-LegacyDialectUpstreamDiff.ps1` 在 2026-11-07 P-D 退役后已失效（它从 `LegacyCompatibilityModules.cs` 读四个名单字段，而名单已迁到 `SnakeLegacySurfaceNames.cs`；目录文件钉的仍是 Skiav10.1 时代的哈希与计数）。改用上游 git 历史做增量审计，并在 `tools/dialect-inventory/README.md` 写明状态。
3. **两个独立 capability 而不是并进既有的**：常数表是新声明语法；`#DIMF CHARADATA` 是对 gemuera 既有「支持一维/二维角色浮点变量」的收紧（上游没有角色浮点 token），分开声明便于包层面单独取舍。
4. **能力未激活时 `CONSTTABLE` 当普通变量名**（照 `OUT` 关键字的先例，`scripts/Emuera/GameProc/UserDefinedVariable.cs:172`）：保证 v24pure 的失败形态与改动前一致（实测为 `書式が間違っています`）。
5. **纯规则层与磁盘层分离**：`ConstArrayTable.cs`（上游逐行移植，分支与文案不变）只依赖 `IConstArrayTableFiles`，从而能像 `ToIntTextParser.cs` 一样被 xUnit 工程直链做 TDD；磁盘实现在 `ConstArrayTableDiskFiles.cs`。
6. **磁盘层走 `uEmuera.Utils` 而不是上游的 `System.IO`**：Android 上文件访问走 Godot 文件 API 与大小写不敏感路径索引，直接用 `Directory`/`File` 在首要目标平台上读不到文件。
7. **读原始行用 `uEmuera.Utils.ReadAllLines(path, Config.Encode)`**：常数表只把行首 `;` 当注释、引号里的 `;` 是普通字符，不能走会按 ERB 规则处理的 `EraStreamReader.ReadEnabledLine`。
8. **名称直接注册并清掉同一键上的惰性登记**：gemuera 的用户定义名是惰性加载（`ConstantData.KeywordLookup.cs` 的 `lazyErdNameData`），上游是即时加载；不清会在首次查找时把旧名字补回来。
9. **`VariableToken.cs` 按规范纯移动拆分**：该文件超过 2000 行，属于「只减不增」，而回填逻辑需要加行。把 `#region float` 整段逐字节搬到 `VariableData.FloatTokens.cs`（命名遵循 `docs/FILE_STANDARD.md` 的「该文件装的是 `VariableData` 的实现，分片须命名 `VariableData.*`」）。
10. **`resources.pak` 本轮不做**：它属资源加载子系统（上游 `ResourceStore.cs` 502 行加 `AppContents.cs` 等多处接入），与解释器无关，需要独立设计并在 Android 上验证。

**排除项（查过、确认无需改动，附依据）**

- `#DIMF` 一至三维：gemuera 已有同名的 `StaticFloat1D/2D/3DVariableToken`、`PrivateFloat1D/2D/3DVariableToken`（`scripts/Emuera/GameData/Variable/VariableToken.cs`、`VariableData.FloatTokens.cs`）。
- 一维数组存档长度保底：上游修的是「读档把 `SparseArray.Length` 覆盖成旧档长度」；gemuera 的四个稀疏读档重载都以 `refArray.ToArray()` 为暂存区再 `FromArray` 回写，长度取自当前声明长度（`scripts/Emuera/Sub/EraBinaryDataReader.cs:427-433`、`:708-714`、`:815-821`、`:931-937`），写出端用 `RawData.Length`（`EraBinaryDataWriter.cs:561-565`）。
- 多维变量内联初值：两侧都在 `sizeNum.Count >= 2` 时报「多次元変数には初期値を設定できません」（`UserDefinedVariable.cs:386-387` 对上游 `UserDefinedVariable.cs` 初值分支）；上游的二维默认值回填只服务于常数表。
- 指令/函数表面：上游 `FunctionIdentifier.cs` 自 2026-06-06（`823c547`）未变，`Creator.cs` 自 2026-11-01（`beadaf0`）未变，17.2 之后零变化，所以冻结表面宇宙与生成清单不需要动。
- eraWire（EWP）：给外部前端用的线协议，与本引擎无关。

**被推翻的中间结论**

- 本会话早先的截图评估（记录已按用户裁定删除）有四处错：把项目名读成「Emuera36A」、把 `#DIMF` 读成 `#DIM`、把 `<div align>` 判成差异（实际已有 `html.div-align-attr-ignore.v1`）、把「多维内联默认值被丢弃」判成差异（实际两侧都拒绝）。
- 我据此在 `AGENTS.md:13` 写入过「已盘点的蛇版能力仍以 Skiav12.1 为准，33 个版本未复核」——错，仓库当时已对齐 17.2；已改为以最近一次对齐日志为准。

**环境障碍与打通**

- `Invoke-LegacyRunner.ps1 -Profile snake` 必然失败于 G10 守卫 `Runner did not load expected first-party pack`（2026-11-21 memory 记为「根因未查」）。本轮查明：守卫在 `godot.log`/`stdout`/`stderr` 里找 Info 级的 `[LOAD] CompatPack enabled`，而用户 `config.toml` 的 `level = "warn"` 会丢弃所有 Info 日志；包加载失败走的是 Error 日志并会触发另一条「回退」报错，本轮未出现。绕行：直接用脚本同样的参数启动 Godot（`--headless --path <仓库> --scene res://tools/legacy-runner/legacy_runner.tscn --language zh --log-file <日志> -- --m0-runner-config=<配置>`，环境变量 `GEMUERA_COMPAT_PACKS=<staging 蛇版包 DLL>`），场景自己写出全部报告；判定口径不变（`state.json` 的 `runnerSuccess`/`exitReason` 与 `display.raw.json` 的 `text`）。
- `tools/pure-move/Test-PureMove.ps1` 的 `-Include` 只补工作区一侧的家族成员，不补基线一侧；对「分片与主文件不同名」的家族，旧分片永远被算成新增。绕行：`-Include` 只传新分片。
- 两个生成物（`LegacyDialectInventories.Generated.cs`、`profiles.generated.json`）在仓库里以 CRLF 提交，但 `.gitattributes` 对它们是 `eol=lf`；生成器重写后内容零差异却显示为已修改。处置：`git checkout HEAD -- <两文件>` 复原（字节可能与生成器输出不同，仅换行符）。
