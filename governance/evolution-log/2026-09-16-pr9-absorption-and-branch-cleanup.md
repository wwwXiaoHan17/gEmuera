## 关键决策与 Why

1. **吸收而非直接 merge**：PR 基线落后 dev 58 提交，7 文件必撞。merge 后逐冲突取
   「PR 拆分结构 + 把 dev 侧增量重放进对应 partial」——而不是反向。Why：拆分是纯
   移动（结构信息），dev 增量是语义（必须保留），以结构为骨架重放语义，验证口径明确。
2. **内容保持性验证 = 行多重集比对**（合并前 dev 原文件 vs 合并后「缩减文件+partials
   合集」，容差=PR 机械行：using/partial/注释/括号/BOM 头）。11/11 通过即证明重放
   字节忠实，比逐行 review 强得多。脚本一次性覆盖全部拆分族，成本极低。
3. **文档去机器特定化标准**：贡献者文档只收「普适经验」（dotnet build 逃生通道、
   MSBuild 陷阱、PowerShell 别名陷阱），必剔「机器断言」（fork 拓扑、D:\ 路径、
   「本机不可用/未安装」）。判断法：把该句放到另一台机器上念，若为假即污染。
4. **VARSETEX 提交（56447a9）不合 dev**：main 血缘、已在 main、dev 无对应文件
   （net diff 无残留）。跨线分支清理先看 `git branch --contains` 与 merge-base 血缘。

## AI 表现复盘

- **有效**：评审先行打分再吸收（55→吸收→95→修复→99 的循环让处置有靶子）；

## 教训 → 具体优化动作

1. **Edit 工具重写 .ps1 会剥 BOM** → PowerShell 5.1 按 ANSI 解析，中文注释/源码拼装
   错乱，报出与真实原因无关的编译错误（行号偏移对不上是识别特征）。
   动作：**每次 Edit .ps1 后立刻 python 补 `utf-8-sig` BOM 再运行**；诊断 PS 脚本
   怪错误时先 `head -c 3 | xxd` 查 BOM。
2. **测试桩与生产语义漂移在「测试损坏」期间静默积累**（ef3ba1d 改了 Driver 等待判定，
   但 Test-LegacyReplay 当时因路径损坏跑不到断言，桩没同步）。动作：修活一个长期
   损坏的测试后，**立即全量跑它**，把「修活后第一轮红」当作语义漂移清单处理。
3. **钉扎文件（sha256）在冲突消解改变被钉文件后必须重钉**（FILE_STANDARD §6.1 的
   吸收场景延伸）。动作：合并涉及钉扎文件时，`hashlib.sha256(open(p,'rb').read())`
   对表重钉；发现存量漂移顺手修（钉扎文件里假哈希比没有更糟）。
4. **GitHub API 匿名请求经代理出口 IP 常年限流**。动作：`git credential fill` 取本地
   token 走认证（token 不回显），配 `-x http://127.0.0.1:7897`。
