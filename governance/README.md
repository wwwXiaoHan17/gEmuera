# Governance — Agent 自我进化机制

本目录是 gEmuera 项目的 **Agent 自我进化基础设施**：每次任务结束后把 AI 的表现、
关键决策、教训与用户提示词模式沉淀为可复用资产，让后续会话的任务效率逐步提升。

## 为什么需要它

- 本项目是 Vibe Coding（AI 主导开发）模式，会话之间互不共享上下文。
- 每次任务中踩过的坑（构建命令、平台限制、设计决策）不沉淀，下次会话会重复踩。
- 用户的提示词习惯（验证检查型、设想型、对齐型…）被识别后，Agent 可以按模式
  直接给出用户期望的输出结构，减少来回确认。

## 目录结构

```text
governance/
├── README.md                # 本文件：机制总览
├── evolution-log/           # 任务复盘进化记录（每次任务一份）
│   └── YYYY-MM-DD-<任务简述>.md
└── prompt-patterns/         # 用户常用提示词模式库
    └── README.md
```

## 流程（每个任务必做，轻量）

1. **任务完成、提交 PR 前**：写一份进化记录到 `governance/evolution-log/`：
   - 任务目标与成果（一句话）
   - 关键决策与 Why（决策 + 理由，供后续任务复用）
   - AI 表现复盘：哪些做法有效、哪些低效（至少各 1 条）
   - 教训 → 具体优化动作（代码/文档/流程）
2. **发现新的用户提示词模式**：补充到 `governance/prompt-patterns/README.md`
   （模式名、特征、推荐应对策略）。
3. **涉及项目规范/流程的教训**：同步更新 `AGENTS.md`（首读文档），
   确保下次会话启动就能看到。
4. 进化记录在 PR 描述中引用（一行即可，如 `进化记录: governance/evolution-log/xxx.md`）。

## 原则

- **轻量**：单文件 markdown，5 分钟内写完，不追求完备。
- **可执行**：每条教训必须落成"下次怎么做"，而不是空泛评价。
- **不删历史**：进化记录只增不改（修正以新文件追加），保证轨迹可追溯。
