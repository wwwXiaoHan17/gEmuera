# 用户常用提示词模式库

收集用户（开发者）在任务中反复出现的提示词结构，Agent 识别模式后按对应策略输出，
减少来回确认、提高一次通过率。来源：任务会话 + git 提交历史归纳。

## 模式速查表

| # | 模式名 | 特征（用户怎么说的） | 应对策略 |
|---|--------|---------------------|---------|
| 1 | 验证检查型 | "检查 X 在 Y 平台是否能正常…"、"确认…是否可用" | 先静态审查平台分支（OS.GetName/HasFeature 门控），再给出结论 + 证据（文件:行）；无法实测时明确标注"需实测项" |
| 2 | 设计设想型 | "我设想的是…"、"我的想法是…" | 优先实现用户设想本身，同时保留原功能语义；把用户设想翻译成具体技术方案时给出决策与 Why |
| 3 | 对齐型 | "对照参考源码"、"减少功能偏移"、"语义对齐" | 修改/优化前对照 `E:\MyCode\Era\emuera.em-master`（v24）或 `emuera_lazyloading_*`（snake），在代码注释里写明对照点 |
| 4 | 审查型 | "检查当前项目是否需要对代码、结构、性能进行优化" | 三维检查（代码质量/结构/性能），按严重度输出问题清单 + 性价比排序建议；不硬凑问题 |
| 5 | 自我进化型 | "实现自我更新/自我进化"、"收集常用提示词" | 任务完成后写 `governance/evolution-log/` 复盘、更新本提示词库、必要时更新 AGENTS.md |
| 6 | 平台双轨型 | 问题同时涉及"移动端/桌面端" | Android 结论必须以 APK 实测为准，桌面仅调试；移动端与桌面分支分别给出行为差异说明 |
| 7 | 改动保护型 | "注意未提交改动"、"避免冲突" | 动手前先 `git status` 识别未提交工作，在其基础上迭代，不覆盖他人/上次会话的成果 |

## 使用方式

- 会话开始时（读完 AGENTS.md 后）快速浏览本表，确认本次任务命中的模式。
- 任务执行中若发现新模式或新模式变体，任务结束时补充到表中。
- 模式库只增不改历史行（修正以追加方式记录）。

## 用户任务风格备注（git 提交历史归纳）

- 提交信息：conventional commits（`feat:/fix:/perf:/docs:/chore:`）+ 中文详细描述。
- 高频主题：性能优化（渲染/输入/启动）、组件化重构、平台适配（Android 优先）、
  功能对齐（对照参考源码）、UI 深色主题统一、i18n 语言文件同步。
- 语言文件改动规律：改 4 个文件（zh_cn / en_us / jp / default）同步更新。
